spicehut_admin_panel

Spice Hut Admin & Backend System

Complete restaurant management system with Flutter frontend and Next.js backend.

📚 Documentation

Main Reference: See COMPLETE_DOCUMENTATION.md for full details.

🏗️ Architecture

  • Frontend: Flutter (Android/iOS/Web/Windows)
  • Backend: Next.js + Node.js
  • Database: MongoDB Atlas
  • Locations: 10 branches

🚀 Quick Start

Backend (Terminal 1)

cd backend
npm start
# Server at http://localhost:4000

Frontend (Terminal 2)

flutter run -d chrome

🔐 Test Login

  • Email: superadmin@spicehut.com
  • Password: See backend .env

🔌 API Endpoints

  • POST /auth/login - Authentication
  • GET/POST/PUT/PATCH/DELETE /orders - Order management
  • GET/POST/PUT/DELETE /menu - Menu management
  • GET/POST/PATCH/DELETE /tables - Table management
  • GET/POST/PUT/PATCH /users - User management
  • GET /analytics - Analytics data
  • GET /branches - Branches list

API Base URL (lib/services/api_service.dart)

// For Physical Device: 'http://192.168.x.x:4000/api'

📦 App Store Publishing Guide

This section covers the full release process for Google Play and Apple App Store.

✅ Shared Prerequisites

  1. Backend is deployed and stable.
  2. App branding is final (icon, name, splash, screenshots).
  3. Privacy policy URL is available (required on both stores).
  4. Store accounts are active:
    • Google Play Console (one-time fee)
    • Apple Developer Program (annual fee)
  5. Verify production API endpoints in lib/services/api_service.dart.

🟢 Google Play Store (Android)

1. Update version

Edit pubspec.yaml and increment:

version: 1.0.0+1
  • 1.0.0 is the app version.
  • +1 is the build number (must increase every upload).

2. Create a release build (AAB)

flutter build appbundle --release

Output file:

build/app/outputs/bundle/release/app-release.aab

3. Configure signing (if not already)

Create a keystore (once):

keytool -genkey -v -keystore upload-keystore.jks -keyalg RSA -keysize 2048 -validity 10000 -alias upload

Create android/key.properties (do not commit):

storePassword=YOUR_STORE_PASSWORD
keyPassword=YOUR_KEY_PASSWORD
keyAlias=upload
storeFile=upload-keystore.jks

Update android/app/build.gradle to use key.properties for the release signing config.

4. Create the app in Play Console

  1. Go to Play Console > Create App.
  2. Fill name, default language, app type, and category.
  3. Complete the "App content" section (privacy policy, data safety, ads, content rating).

5. Upload release

  1. Go to Production > Create release.
  2. Upload the .aab file.
  3. Add release notes.

6. Store listing assets

  • App icon (512x512)
  • Feature graphic (1024x500)
  • Screenshots (phone and tablet recommended)
  • Short and full descriptions

7. Submit for review

Review warnings and submit. Typical review time: hours to a few days.

🍎 Apple App Store (iOS)

1. Update version

Same pubspec.yaml change as Android. Build number must increase for every upload.

2. Build release IPA

flutter build ipa --release

Output:

build/ios/ipa/*.ipa

3. Configure signing in Xcode

Open iOS project:

open ios/Runner.xcworkspace

In Xcode:

  • Set the correct team
  • Confirm bundle ID matches App Store Connect
  • Ensure provisioning profile is valid

4. Create the app in App Store Connect

  1. Go to App Store Connect > My Apps > New App.
  2. Fill app name, bundle ID, SKU, and language.

5. Upload the build

Use Xcode Organizer:

  1. Product > Archive
  2. Distribute App > App Store Connect

Alternative: use Apple Transporter to upload the .ipa.

6. Store listing assets

  • App icon
  • Screenshots (required sizes for iPhone and iPad)
  • Description, keywords, support URL, privacy policy URL

7. App Privacy and Review

Complete the App Privacy questionnaire and fill review info, then submit.

🍏 iOS-Specific Configuration (Required)

1. Info.plist permissions

Ensure the required permission strings exist in ios/Runner/Info.plist:

  • NSCameraUsageDescription
  • NSPhotoLibraryUsageDescription
  • NSPhotoLibraryAddOnlyUsageDescription
  • NSMicrophoneUsageDescription
  • NSBluetoothAlwaysUsageDescription
  • NSBluetoothPeripheralUsageDescription
  • NSLocalNetworkUsageDescription

2. Background audio mode (ringtone support)

To allow ringtone playback when the app is not in the foreground, iOS needs background audio:

  • UIBackgroundModes includes audio (already configured in Info.plist).

3. Push notifications (optional, for true background alerts)

This app currently uses HTTP polling for new orders. iOS will not run polling while the app is suspended. If you need background alerts, you must implement APNs push notifications:

  1. In Xcode: enable Push Notifications capability.
  2. In Xcode: enable Background Modes > Remote notifications.
  3. Add an aps-environment entitlement (Xcode does this automatically).
  4. Implement push handling in Flutter (e.g., Firebase Messaging).
  5. Configure APNs keys in Apple Developer portal and in your backend.

✅ Final Release Checklist

  • Version + build number updated
  • Release build signed
  • Store listings completed
  • Privacy policy URL added
  • App content / privacy forms completed
  • Release notes added
  • Submitted for review

🛠️ Troubleshooting

  • Connection refused: Check backend is running, verify baseUrl
  • Login fails: Check credentials, verify MongoDB connection
  • White screen: Try flutter clean, check internet permission
